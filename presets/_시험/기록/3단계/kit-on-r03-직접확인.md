## 결과-나누기 / 페이지-번호 — 많은 행을 쪽으로 나눠 보일 때

근거: '거래처가 800곳' — 100개를 넘으므로 한번에-전부가 아니고, 최신순 피드도 아니다. '몇 번째를 다시 찾아간다'는 적혀 있지 않지만 남은 두 줄(다시 찾아감 / 정보 없음) 모두 페이지-번호다.

어디를: 대상 = 표의 행 · 첫항목 = 2번째 표의 행 · 다음쪽 = 버튼 “다음 쪽”

- [ ] 한 쪽에는 정해진 수만 보인다
- [ ] 다음 쪽으로 가면 다른 항목이 보인다
- [ ] 규칙: 표 아래에 쪽 번호와 [이전]·[다음]을 두고, 전체 건수와 지금 범위("41–60 / 1,240")를 적는다. 한 쪽 크기는 고를 수 있게 해도 된다.
- [ ] 금지된 모양이 없다: 끝없이 이어 붙이기(위치를 다시 찾을 수 없다). 전체 건수를 숨기기.

## 필터-적용 / 즉시-적용 — 조건을 바꾸면 결과가 곧바로 바뀌어도 될 때

근거: '800곳 정도' — 수만 건 이상이 아니고 기간 조건도 없어 결과가 가볍다. 이름·지역·담당자는 바꾸는 즉시 반영한다.

어디를: 대상 = 표의 행 · 조건바꾸기 = 입력칸 “거래처 이름 검색”에 “윤슬테크” 입력 · 초기화 = 1번째 버튼 “초기화”

- [ ] 조건을 바꾸면 버튼 없이 결과가 바로 바뀐다
- [ ] 초기화하면 처음 결과로 돌아온다
- [ ] 규칙: 검색칸·고르기를 바꾸는 즉시 결과를 다시 보인다. 검색칸은 글자를 멈춘 뒤 반영해도 된다. 조건 줄 끝에 **초기화**를 둔다.
- [ ] 금지된 모양이 없다: 가벼운 목록에 [검색]·[적용] 버튼을 따로 두기. 초기화 없이 조건을 여럿 두기.

## 일괄-선택 / 일괄-작업-줄 — 여러 항목을 골라 한꺼번에 처리할 때

근거: '여러 거래처를 골라 담당자를 한 번에 바꾸는 기능' — 고른 항목들에 한꺼번에 할 동작이 있다. 여러 쪽에 걸친 '전부'를 처리한다는 말은 없다.

어디를: 일괄줄 = 작업 줄 “일괄 작업” · 항목선택 = 2번째 표 본문 안의 체크칸

- [ ] 아무것도 고르지 않으면 일괄 동작이 보이지 않는다
- [ ] 고르면 일괄 동작과 고른 개수가 보인다
- [ ] 규칙: 항목마다 고르기 칸을 두고, **하나라도 고르면** 목록 위에 일괄 작업 줄이 나타난다. 줄에는 고른 개수와 동작 버튼, 선택 해제를 둔다. 머리 칸의 고르기는 보이는 항목 전체를 고른다.
- [ ] 금지된 모양이 없다: 일괄 동작 버튼을 늘 보이게 두고 비활성으로 막기. 고른 개수를 보여주지 않기.

## 삭제 / 강한-확인 — 되돌릴 수 없고 딸린 것까지 지워질 때

근거: '거래처를 삭제하면 그 거래처의 계약과 메모도 모두 같이 지워져' — 딸린 데이터까지 함께 지워진다. 휴지통·복구 기간 언급이 없어 되돌릴 수 없다고 본다(확인 필요).

어디를: 시작 = 2번째 표의 행 안의 버튼 “더보기” → 메뉴 항목 “삭제” · 확인창 = 확인창 · 확정 = 확인창 안의 버튼 “삭제” · 입력 = 확인창 안의 입력칸 · 지울것 = 표의 행 “가람개발”

- [ ] 대상 이름을 직접 입력하기 전에는 확정할 수 없다
- [ ] 입력하고 확정하면 대상이 사라진다
- [ ] 규칙: 확인창에 **함께 지워지는 것**을 개수와 함께 적는다. 대상의 이름을 그대로 입력해야 확정 버튼이 눌린다. 버튼 옆에 왜 못 누르는지 적는다.
- [ ] 금지된 모양이 없다: 일반 확인창으로 끝내기. 체크박스 하나로 대신하기.

## 행-동작-위치 / 행-끝-메뉴 — 행마다 동작이 여럿일 때

근거: 행마다 동작이 둘이다 — 그 거래처만 담당자 변경, 삭제.

어디를: 행버튼 = 2번째 표의 행 안의 버튼 · 메뉴열기 = 2번째 표의 행 안의 버튼 “더보기” · 메뉴 = 메뉴

- [ ] 행 안에 보이는 동작 버튼은 메뉴 버튼 하나다
- [ ] 메뉴를 열면 그 행의 동작이 모여 있다
- [ ] 규칙: 행 끝에 **더보기(⋯) 메뉴 버튼 하나**만 두고, 동작은 메뉴 안에 모은다. 파괴적 동작은 메뉴 맨 아래 `destructive`.
- [ ] 금지된 모양이 없다: 행마다 [편집][복제][삭제] 버튼을 나란히 두기.

## 결과-알림 / 토스트 — 동작이 성공했음을 알릴 때

근거: 담당자 변경·삭제가 성공하면 이어서 목록 작업을 계속한다. 실패 처리에 대한 정보는 없다(확인 필요).

어디를: 시작 = 2번째 표 본문 안의 1번째 체크칸 → 2번째 표 본문 안의 2번째 체크칸 → 작업 줄 “일괄 작업” 안의 버튼 “담당자 변경” → 고르기 “새 담당자” → 선택지 “한지우” → 창 안의 버튼 “변경” · 결과 = 글자 “담당자를 바꿨습니다”

- [ ] 동작이 끝나면 결과 알림이 나타난다
- [ ] 알림이 화면 조작을 막지 않는다
- [ ] 규칙: 토스트로 알린다. 제목은 **무엇이 어떻게 됐는지**("3개 계정을 비활성화했습니다"). 사용자의 흐름을 막지 않는다.
- [ ] 금지된 모양이 없다: 성공을 대화상자로 알리기(닫기를 한 번 더 누르게 된다). "성공했습니다"처럼 대상이 빠진 문구.

## 기다림-표시 / 버튼-로딩 — 짧은 동작이 끝나기를 기다릴 때

근거: 담당자 일괄 변경은 몇 초 안에 끝나는 저장 동작이다(소요 시간 정보 없음 → 기본).

어디를: 시작 = 2번째 표 본문 안의 1번째 체크칸 → 작업 줄 “일괄 작업” 안의 버튼 “담당자 변경” → 고르기 “새 담당자” → 선택지 “한지우” → 창 안의 버튼 “변경”

- [ ] 누르면 끝날 때까지 그 버튼이 기다리는 표시를 하고 다시 눌리지 않는다
- [ ] 규칙: 누른 그 버튼에 `loading` 을 준다 — 너비는 그대로, 다시 눌리지 않는다. 끝나면 결과를 알린다. 목데이터에서도 1초쯤 지연을 흉내 낸다.
- [ ] 금지된 모양이 없다: 화면 전체를 덮는 로딩. 누른 뒤 아무 표시 없이 기다리게 하기(두 번 누르게 된다).

## 에이전트가 망설인 것 — 사람이 정할 것

- 삭제를 되돌릴 수 있는가 — 요구에 휴지통·복구 기간이 없어 '되돌릴 수 없음'으로 보고 강한 확인(이름 입력)을 골랐다. 복구가 된다면 즉시-되돌리기로 바뀐다.
- 여러 쪽·검색 결과 전체를 한 번에 고르는 기능('검색 결과 800곳 모두')이 필요한가 — 적혀 있지 않아 머리 칸 고르기는 보이는 쪽만 고른다. 고른 것은 쪽을 넘겨도 유지된다.
- 여러 거래처를 한 번에 삭제하는 기능은 넣지 않았다 — 딸린 계약·메모까지 지워지는 동작이라 한 곳씩 이름 입력으로만 지운다.
- 거래처 새로 등록·상세 보기는 요구에 없어 넣지 않았다. 빈 상태의 다음 행동도 그래서 '다시 불러오기'다.
- 담당자 변경·삭제가 실패했을 때의 처리(권한 없음 등)는 정보가 없어 화면 안 알림을 두지 않았다.
- 쪽당 20곳. 기본 정렬은 거래처명 가나다순.
