# 화면 만들기

이 키트는 `src/kit/` 에 있다. **정해진 순서대로만 읽는다.** 전체를 먼저 훑지 않는다.
`src/screens/` 의 **다른 화면은 열지 않는다** — 다른 요청으로 만든 것이라 이번 요청의 답이 아니다.
**어떤 요청이든 화면은 만든다.** 맞는 셸이 없으면 자유 화면 셸(`free`)로 짓는다(2단계). 멈추지 않는다.

## 1. 목록부터 읽는다

`src/kit/index.json` 하나만 연다. 셸과 정책의 **제목·조건만** 들어 있다.

## 2. 셸을 고른다

- `shells` 에서 요구사항에 맞는 것을 하나 고른다. 비슷한 셸이 둘 이상이면 각 셸의 `쓰지 않는 때` 를
  읽고 **왜 저쪽이 아닌지** 적을 수 있어야 한다.
- 둘 이상이 똑같이 맞아 보이면 하나를 고르되, 망설인 이웃과 이유를 `확인 필요` 에 적는다.
- 셸의 구조는 그대로 두고 **요소를 더해야 하면** 확장 자리를 쓴다 — `lead`(본문 위 한 줄: 요약 카드 줄 · 안내),
  `side`(본문 오른쪽 칸: 최근 활동 · 도움말). 셸마다 어떤 자리가 있는지는 `shell.json` 의 슬롯에 있다.
  **칸 안에 억지로 끼워 넣지 않는다**(표 칸 안에 옆 패널을 짜 넣는 것 등).
- **맞는 셸이 없으면** `맞는 셸이 없을 때` 의 `free` 로 짓는다. 비슷한 셸에 억지로 끼워 넣지도, 멈추지도 않는다.
  바깥 틀 · 면 · 간격 · 상태 칸은 `free` 가 맡고, 본문만 부품과 계약 토큰으로 자유롭게 짓는다.
  명세의 `셸` 에 `"가장 가까운"`(셸 id)과 `"부족한 점"`(무엇이 없어서 기존 셸로는 안 되는가)을 적는다.
- 한 화면이 **여러 셸을 오가면**(목록 → 상세 → 새로 만들기 폼) 처음 보이는 셸을 `셸` 에, 나머지를 `추가 셸` 에 적는다.

## 3. 정책을 고른다

- `policy` 의 결정마다 `상황` 을 읽고, 요구사항에 해당하는 결정을 모두 고른다.
- 고른 결정마다 **결정표를 위에서부터 읽어 맞는 첫 줄의 유형 하나**를 고른다.
  조건은 요구사항에 **적힌 사실**로만 판단한다. 적혀 있지 않으면 "정보가 없다" 줄을 쓰고 `확인 필요` 에 남긴다.
- **정책에 맞추려고 요구에 없는 기능을 만들지 않는다.** 예: 행 동작이 삭제 하나뿐이면 결정표대로 `행-버튼` 이다 —
  메뉴를 쓰려고 "옮기기" 같은 동작을 지어내지 않는다. 기능이 더 있으면 좋겠다고 보이면 만들지 말고 `확인 필요` 에 적는다.
- 카드의 `적용 셸` 에 고른 셸이 없으면 그 카드는 쓰지 않는다.

## 4. 고른 것만 연다

고른 셸의 `shell.json` · `shell.tsx`, 고른 카드 파일만 연다. 셸에 `예시` 가 있으면 그것도 연다 — 칸 안을 채우는 모양의 기준이다.
다른 셸 · 카드는 열지 않는다. **검사 도구(`scripts/agent-kit/*`)의 소스는 열 필요가 없다** — 쓰는 법은 이 문서 5절에 다 있다.

## 5. 명세를 쓴다 — 구현보다 먼저

`src/screens/<화면-id>/명세.json`

화면 id: 요청 앞에 `[r03]` 처럼 대괄호가 있으면 그 값을 쓴다. 없으면 짧은 영어 id 를 짓는다(`accounts`).

```json
{
  "요구 요약": "",
  "주소": "#/<화면-id>",
  "데이터": { "필드": [], "목데이터": "셸의 최소 데이터 이상" },
  "셸": { "id": "", "이유": "", "제외한 이웃": [{ "id": "", "이유": "" }] },
  "추가 셸": [{ "id": "", "쓰는 곳": "상세를 누르면" }],
  "슬롯": { "<셸의 슬롯 이름>": "무엇을 넣는가 — 상태 슬롯이 해당 없으면 { \"없음\": \"이유\" }" },
  "정책": [{ "id": "", "근거 조건": "요구사항의 어느 말 때문에 이 유형인가" }],
  "실패 흉내": { "<동작 이름>": "무엇이 실패하는가" },
  "경로": { "<카드 id>": { "<카드 단계가 쓰는 이름>": { "역할": "button", "이름": "삭제" } } },
  "확인 필요": []
}
```

`free` 로 지을 때 `셸` 은 `{ "id": "free", "이유": "", "가장 가까운": "<셸 id>", "부족한 점": "", "제외한 이웃": [...] }`.
`추가 셸` · `실패 흉내` 는 해당할 때만 쓴다.

### 경로 쓰는 법

**경로**는 고른 카드의 `보장` → `단계` 에 나오는 이름(시작 · 확인창 · 확정 · 취소 · 결과 · 대상 · 지울것 …)을
**내 화면의 요소**에 잇는 것이다. 카드 파일의 `단계` 에 쓰인 이름을 **모두** 적는다(검사기가 빠진 이름을 알려 준다).

요소 하나는 이렇게 가리킨다.

| 칸 | 뜻 | 예 |
|---|---|---|
| `역할` | 접근성 역할 | `button` `menuitem` `checkbox` `textbox` `combobox` `option` `row` `table` `dialog` `alertdialog` `switch` `toolbar` `list` `link` `tab` `alert` `meter` `progressbar` `heading` `region` |
| `이름` | 접근 가능한 이름 — **부분 일치** | 버튼 글자, `aria-label`, 연결된 레이블 |
| `글자` | 역할이 없는 요소를 글자로 (역할 대신) | 칸 아래 오류 문구, `listitem`(목록 항목은 이름이 잡히지 않는다) |
| `순번` | 같은 것이 여럿이면 몇 번째(0부터) | 표의 첫 데이터 행은 머리 행 다음이라 `1` |
| `안` | 이 요소 안에서만 찾기 — 다른 경로 이름이나 요소 | `"안": "확인창"`, `"안": { "역할": "table", "이름": "직원 계정" }` |
| `입력` | 누르지 않고 이 글자를 넣는다 (여러 단계 경로 안에서) | `{ "역할": "textbox", "이름": "검색", "입력": "김" }` |

- 여러 번 눌러야 닿으면 배열로 쓴다: `"시작": [{ "역할": "button", "이름": "더보기" }, { "역할": "menuitem", "이름": "삭제" }]`
- 값(입력할 글자, 쪽당 개수 등)은 **문자열**로 적는다: `"입력값": "강민준"`, `"한쪽개수": "11"`.
- 보장이 어떤 상태에서만 보이면(고른 뒤에만 나오는 막대 등) 그 카드 경로에 `준비`(먼저 누를 것)를 적는다.
- 실패를 보는 카드(`실패로열기`)는 경로에 **동작 이름**(문자열)을 적고, 코드에서 그 동작을 `useShellFail()` 로 감싸고,
  명세 `실패 흉내` 에 같은 이름을 적는다.
- 목데이터에서 **결과가 실제로 달라지는** 조건·항목을 고른다(바꿔도 수가 같으면 검사가 알아볼 수 없다).

단계가 하는 일 — 경로를 어디에 이을지 판단할 때 본다:

| 단계 | 하는 일 |
|---|---|
| `누르기` | 그 요소를 누른다 (배열이면 차례로, `입력` 칸이면 글자를 넣는다) |
| `보인다` · `안보인다` | 그 요소가 보이는가 · 사라졌는가 (4초까지 기다린다) |
| `기억` → `개수` | 그 요소의 개수를 기억했다가 늘었는지 · 줄었는지 · 같은지 · 정해진 수인지 본다 |
| `기억글자` → `글자` | 글자를 기억했다가 바뀌었는지 · 그대로인지, 또는 어떤 글자를 포함하는지 본다 |
| `입력` · `값` | 입력칸에 글자를 넣는다 · 입력칸의 값을 확인한다 |
| `떠나기` | 입력칸에서 다른 곳으로 옮긴다 (Tab) |
| `비활성` · `활성` · `바쁨` | 버튼이 눌리지 않는가 · 눌리는가 · 기다리는 표시(`loading`)를 하는가 |
| `막힘없음` | 화면을 막는 창이 떠 있지 않은가 (토스트는 막지 않는다, 확인창은 막는다) |
| `기다리기` · `다시열기` · `실패로열기` | 몇 초 기다린다 · 새로 고친다 · 그 동작이 실패하도록 다시 연다 |

## 6. 구현한다

- `src/screens/<화면-id>/index.tsx` 에 `export default function Screen()` 하나.
- 고른 셸 컴포넌트를 `@/kit/shells/<셸-id>/shell` 에서 가져와 **그 슬롯에 채운다.** 셸의 레이아웃을 흉내 내어 새로 짜지 않는다.
- 화면 상태는 직접 계산한 뒤 `useShellState(계산한 상태)` 를 거쳐 셸에 넘긴다(검사기가 상태를 바꿔 띄워 본다).
- 부품은 `@/components/ui/*`, 아이콘은 `@/lib/ax/icons` 에서만 가져온다. 클래스는 계약 토큰만(AGENTS.md 1절).
- 부품에 없는 것(차트 · 캘린더 격자 등)이 필요하면 부품과 계약 토큰으로 조립한다. 새 색·치수를 지어내지 않는다.
- **디자인시스템 파일은 고치지 않는다** — `src/components/ui/*` · `src/lib/ax/*` · `src/kit/*`. 부품에 기능이 모자라면(예: 확인창 버튼에 로딩)
  화면 쪽에서 부품을 조합해 만들고, 모자란 점을 `확인 필요` 에 적는다. 필요한 아이콘이 `icons` 에 없어도 같다 — 비슷한 아이콘을 쓰고 적는다.
  (여러 화면이 같은 부품을 쓴다. 한 화면을 위해 부품을 고치면 다른 화면이 조용히 바뀐다.)
- 목데이터는 `src/screens/<화면-id>/data.ts` 에 따로 두고 **첫 줄에 `/* ax-lint-disable-file — 목데이터 */`** 를 쓴다.
  데이터 문자열이 클래스 검사에 걸리지 않게 하는 표시다. 이 파일에는 클래스를 쓰지 않는다. 셸의 `최소 데이터` 이상.

## 7. 검사하고 고친다

이 앱에서 쓰는 검사는 이 두 개다. (AGENTS.md 에 적힌 `npm run verify` 는 디자인시스템 저장소의 명령이라 여기에는 없다.)

```bash
node scripts/agent-kit/check-screen.mjs src/screens/<화면-id>
node scripts/agent-kit/run-scenario.mjs src/screens/<화면-id>
```

둘 다 통과할 때까지 고친다. **통과하지 못해도 화면은 남긴다** — 이유를 명세의 `확인 필요` 에 적고 끝낸다.
